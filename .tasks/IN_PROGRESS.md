    - **Gate pin/body misalignment (visually confirmed via screenshot, affected every gate type, not only single-input ones as originally scoped):** `variadicGatePorts`' output `Y` offset used `(count - 1) / 2`, but the Canvas2D and SVG renderers both always draw a gate's output tip at `Math.max(2, inputCount) / 2` (half the actual drawn body height) — so a plain 2-input AND/OR/NAND/etc.'s own output pin/wire-endpoint was already about half a grid row above its visual tip before any single-input gate was involved; single-input gates (NOT/BUFFER) and the tri-state buffer's output were worse, sitting a full row off (at the un-padded top edge instead of the padded body's center). Fixed in `component-library.ts` by deriving every affected offset from one shared `gateBodyRows(inputCount) = Math.max(2, inputCount)` helper (`Y` at `gateBodyRows(count) / 2` for variadic gates; `A`/`Y` at `gateBodyRows(1) / 2 = 1` for NOT/BUFFER; `Y` at `gateBodyRows(2) / 2 = 1` for the tri-state buffer), so `render-engine.ts` and `export-engine.ts` need no changes — they already derived body height the same way, so pin offsets now agree with the geometry they already draw. This was the deferred "single-input gate centering" item, but the actual root cause and fix were broader than that description; the design/plan wording is updated accordingly.
