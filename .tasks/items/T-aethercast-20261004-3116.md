# Judge inversion night hours in the dataset's timezone

## Request
Found while covering AEC-R14: `detectAnomalies` in `src/tools/aethercast/aethercast-anomaly.ts` decides "overnight" with `new Date(isoTimestamp).getHours()`, which is the viewer's browser timezone. For timestamps with an explicit UTC offset or `Z` (CSV and AetherCast JSON imports), the hour is the viewer's, not the location's: `2026-06-01T14:00:00+09:00` viewed in a UTC browser is hour 5 (night), so a daytime calm, rising-pollutant window is screened as a thermal inversion. Wall-clock strings without an offset (live Open-Meteo data) are unaffected.

## Resume here
Done. AEC-R23 `verified`: `detectAnomalies(points, timezone)` reads night hours with `datasetLocalHour` (hour as written for wall-clock and numeric-offset timestamps; dataset IANA timezone, else UTC, for `Z`).
